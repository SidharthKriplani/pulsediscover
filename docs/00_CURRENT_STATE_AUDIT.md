# 00 — PulseDiscover Current-State Audit

*Source of truth: direct code audit of `GitHub/pulserank_platform` (captured in `archive/PulseOS_BeastMax_Architecture_Review.md`) + the gold PRD (`docs/PRD_PulseDiscover_v2.md`). This audit determines what the BeastMax build must produce as new evidence.*

**Tags:** `[BUILT]` · `[BUILT][SYNTHETIC]` · `[REAL-READY]` (public data exists, not yet used) · `[VISION]` · `[BUILD-TASK]` · `[OVERCLAIM→DELETE]` · `[CAUTIONARY]`.

## 1. What is already built `[BUILT][SYNTHETIC]`
Inside `pulserank_platform/src` (real code → versioned JSON artifacts, on a synthetic e-commerce corpus):
- From-scratch **ALS** (32 factors, confidence-weighted implicit MF).
- Item-item **co-occurrence** (session PMI).
- **LightGBM LambdaRank** ranker (listwise), serialized + model card.
- **IPS + SNIPS** off-policy evaluation with position-based propensity + **clipping-sensitivity sweep** `[5,10,20,50,100]`.
- **MMR** governed reranking (seller caps, category-share caps, audit log).
- Hybrid candidate generation (popularity + content + ALS + co-occ).
- Delayed attribution (1/3/7-day), **Gini**, offline **A/B replay** with guardrail decisioning.
- Drift monitoring (KL, PSI).
- FastAPI serving stub + batch scoring (not deployed).
- 61 test functions; CI config; pytest cache shows no recorded failures (not run live this session).

## 2. What is synthetic `[BUILT][SYNTHETIC]`
- 100% of data is generated by `scripts/seed_demo.py` (seed 20260505): 900 users, 650 items, 80 sellers, 90 days, **4,132 sessions, 41,320 impressions**.
- Position bias is a hardcoded `PROPENSITY_BY_RANK` curve; 5% epsilon-greedy exploration; cold-start flags; lognormal prices; returns.
- "Content embeddings" are **8-dim random uniform** (collaborative signal only, not semantic).
- Domain is **e-commerce (sellers/GMV/returns)**, NOT serialized fiction.

## 3. What is real / public-data-ready `[REAL-READY]` (exists, not yet used)
- **MovieLens-1M/25M** — public, ready; smoke-test only.
- **Goodreads (UCSD Book Graph)** — public; domain-aligned (books, series, authors); the headline-dataset candidate. Not yet downloaded/used.
- **Amazon Reviews (Books)** — public fallback.
- None of these are wired into any code yet.

## 4. What is `[VISION]` (designed in PRD, no code)
- Two-tower retrieval; SASRec sequential ranker; **Doubly-Robust (DR)** OPE; **PAL** additive position tower; semi-synthetic **known-propensity simulator**; feedback-loop **Shapley** exposure audit; LightGCN; multi-objective constrained ranking.

## 5. What is `[BUILD-TASK]` (the work this plan schedules)
- Build the known-propensity simulator; implement DR (correct formula `V_DR=DM+(1/p)(r−q̂)`); add SASRec + two-tower on a public dataset; PAL vs IPS comparison; feedback-loop audit; **bootstrap/Wilson CIs on every offline number** (current biggest evidence gap); reproducible evidence JSONs + plots; PRD update; defense PDF.

## 6. Overclaim / delete / cautionary
- `[OVERCLAIM→DELETE]` **"0.134 → 0.522 improvement."** Per `INTERVIEW_SAFE_CLAIMS.md`, these are different evaluation frames on different subsets — NOT a before/after. Honest figure: IPS bias_delta **−0.0053**.
- `[CAUTIONARY]` ALS scores are **0.0 in the ranker's training features** — retrieval and ranker are not wired (documented disconnect, a build-task to fix).
- `[CAUTIONARY]` "content embeddings" are random 8-dim — not semantic; two-tower is the real upgrade.
- `[CAUTIONARY]` MMR improved category share but **worsened seller Gini 0.404→0.582** — keep as the honest tradeoff.
- Do **not** retro-claim the e-commerce repo as a fiction recommender.
